# dsh-meter

DeepSeek Harness Web 的用量计费展示插件：在输入框上方右侧显示三个单行胶囊。

| 胶囊 | 内容 |
| --- | --- |
| 时段 | `高峰 09:00-12:00` / `低峰 18:00-24:00`（北京时间，每 30 秒自动切换，高峰橘黄高亮） |
| 消费 | `消费 ¥x.xxxx`（悬停见按价位段分账明细、模型版本、缓存命中率、当前单价） |
| 余额 | `余额 ¥x.xx` + 币种（每 5 分钟自动刷新） |

## 计费口径：带时间戳的本地价位表历史

价位表按**时段（era）**维护，每个时段有生效时间区间、当天的高峰规则、以及该时段服务的模型版本与单价。
核算时**逐请求按其发生时刻所属时段的价目**计算，因此跨越调价的会话不会被重定价。

### 内置时段

| 时段 id | 生效区间（北京时间） | 高峰规则 | flash 价（命中/未命中/输出，元/百万） | pro 价 |
| --- | --- | --- | --- | --- |
| `peak-valley` | 2026-08-17 起 | 每日 09:00-12:00、14:00-18:00 | 0.05 / 0.10 — 1.5 / 3.0 — 4.5 / 9.0 | 0.15 / 0.30 — 4.5 / 9.0 — 13.5 / 27.0 |
| `v4.1-flash` | 2026-09-10 起 | 工作日（周一至周五） | 0.02 / 0.04 — 1.0 / 2.0 — 4.0 / 8.0 | 0.15 / 0.30 — 4.5 / 9.0 — 13.5 / 27.0 |
| `v4-pro-via-v4.1-flash` | 2026-09-14 12:00 起 | 工作日 | 0.02 / 0.04 — 1.0 / 2.0 — 4.0 / 8.0 | 同 flash（官方公告：Pro 请求路由至 V4.1 Flash 并按 Flash 计价） |

（每格为「缓存命中 谷/峰 — 缓存未命中 谷/峰 — 输出 谷/峰」；谷价 = 峰价的一半。数据来源：DeepSeek 官方「模型 & 价格」页与更新日志。）

### 模型版本

| 模型 id | 版本 | 备注 |
| --- | --- | --- |
| `deepseek-flash` | DeepSeek-V4.1-Flash | 当前主模型（2026-09-10 上线） |
| `deepseek-v4-flash` | DeepSeek-V4-Flash | 已下线，请求路由至 V4.1-Flash，按 Flash 计价 |
| `deepseek-v4-flash-vision-exp` | DeepSeek-V4-Flash-Vision-Exp | 已下线，同上 |
| `deepseek-v4-pro` | DeepSeek-V4-Pro-0813 | 2026-09-14 12:00 后路由至 V4.1 Flash 并按 Flash 计价 |

### 维护方式

价位表是 `src/index.js` 顶部的 `PRICE_HISTORY` 常量（新时段放在数组最前，`to: null` 表示当前时段）。
新增调价时：把现有最新时段的 `to` 设为新时段的生效时刻，并在数组头部插入新时段。

```bash
node scripts/build.mjs          # 生成 lib/ 产物（纯 JS，无编译步骤）
node scripts/verify-pricing.mjs # 校验跨时段/工作日高峰规则核算是否正确
```

## 安装

```bash
# 需要 pnpm（dsh plugin 用它管理 profile 插件）
dsh plugin --profile web add https://github.com/Rieide/dsh-meter.git
```

首次安装后需在插件设置中授权该插件（浏览器端 UI）。

余额查询依赖 `DEEPSEEK_API_KEY`：在 Web 的 Models 设置页写入，或启动环境导出该变量。

> 消费为估算值（按本地价位表历史核算），以官方账单为准。
